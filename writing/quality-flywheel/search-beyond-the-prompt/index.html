Search Beyond the Prompt

An optimizer can only discover changes its search space allows.

The team now knows something specific: Atlas's summary concealed the difference between authentication failure and overload. It could add another paragraph to the prompt. It could improve the summary tool. It could give Atlas a focused investigation step. These are different interventions, not interchangeable ways of asking the model to try harder.

A prompt optimizer cannot invent a response-code field if the tool interface never exposes one. It may instead discover that credential incidents are common in the development set and learn to guess “refresh the key.” The score rises until the next queue is caused by something else.

Every hill has a boundary

Hill climbing starts with a candidate, tries nearby changes, and retains an improvement. For Atlas, a nearby change might be a sentence in the prompt. The score defines uphill; the allowed edits define which neighboring candidates exist.

A local peak means that none of the nearby changes being tried looks better. It does not mean the best system has been found. Rewording “investigate carefully” may stop helping because the limiting factor is missing evidence. Expanding the tool output changes what the search can explore.

There are practical reasons to search locally: small changes are cheap, easier to inspect, and easier to reverse. The mistake is treating the best result within one search space as evidence that the surrounding architecture no longer matters.

Use the failure to propose a change

A score can rank a candidate against a baseline. It says little about what to try next. A trace saying “the assistant inferred overload from queue depth before inspecting the 401 responses” suggests a narrower intervention.

That distinction runs through several strands of research. DSPy makes language-model programs modular enough to optimize their components. TextGrad propagates natural-language feedback through a computation. Its “gradients” are critiques, not exact derivatives; their value lies in proposing useful edits that can be tested.

GEPA uses execution feedback to evolve prompts and retain candidates with complementary strengths. This matters when a single average hides useful differences. A candidate that handles authentication incidents well and another that handles throttling well may provide more material for the next revision than the current overall winner alone.

For Atlas, the team puts three candidates on the table:

  1. Prompt: require a specific piece of evidence for the proposed cause.
  2. Tool: include response-code distribution and credential-version metadata in the incident snapshot, without exposing the credentials themselves.
  3. Procedure: inspect the error class, compare affected and healthy workers, then choose a reversible mitigation.

Test them separately before combining them. If the richer snapshot fixes the development cases while the prompt alone does not, the evidence favors changing the information interface. If the combination helps, the interaction deserves its own comparison. An elaborate rewrite that changes everything at once makes it harder to know which part was worth keeping.

Keep a cost for being clever

A procedure that calls twelve tools before every recommendation might raise accuracy and make Atlas unusable during an incident. A better design could start with a cheap error summary and request the detailed comparison only when the evidence is ambiguous.

The search therefore needs more than a quality score. It needs the operator's time budget, tool costs, and limits on side effects. AI Agents That Matter argues for evaluating agent performance together with its cost and for more careful benchmark design. For Atlas, a useful result is a better diagnosis at an acceptable operational cost.

The frontier here is increasingly about generating better interventions from experience. But proposal quality and evidence of improvement remain separate problems. A convincing explanation of why an edit should work is a reason to run the experiment, not a substitute for its result.
